# EN/DE i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build real static German pages under `/de/` with an EN | DE switcher, where untranslated strings fall back to English one key at a time.

**Architecture:** German data files in `src/de/_data/` deep-merge over the English JSON, so Eleventy's existing data cascade localises the *current* templates with zero template forks. `localePath()` in `.eleventy.js` keeps internal links inside the active locale. The switcher is a plain link, no JavaScript.

**Tech Stack:** Eleventy 2.0.1, Nunjucks, static output to `docs/`. No new dependencies.

**Spec:** `specs/2026-10-05-coffee-qr-and-i18n-design.md` (Part B)

## Global Constraints

- Site is served from the domain root, so **root-relative URLs are valid** and required.
- English files in `src/_data/` are the single source of truth. Never edit them to add German.
- Every German data file starts from its complete English counterpart, so per-key fallback is automatic. Omit a key and English is served.
- CV content stays English by design: `resume.work_experience[*]`, `resume.education[*]`, `projects.topics[*].articles[*].title`.
- The locale is derived from `page.url`. Do **not** add `lang:` front matter; it can drift.
- `docs/` is build output and is deleted on a clean build. Stop Eleventy before editing sources, rebuild, restart — the watcher deletes passthrough assets like `docs/js/jquery.min.js` and every check then errors.
- Verification script lives at `C:\Users\dummy\AppData\Local\Temp\opencode\verify.mjs`, outside the repo. Run `node "<that path>"`. Exit 1 = failures.
- Rebuild recipe used by every task:

```powershell
Stop-Process -Id (Get-NetTCPConnection -LocalPort 8080 -State Listen).OwningProcess -Force
Remove-Item -Recurse -Force docs
npx @11ty/eleventy
Start-Process npx -ArgumentList "@11ty/eleventy","--serve","--port=8080" -WindowStyle Hidden
```

## Review Focus

- **A German overlay key that no longer exists in English.** The merge silently ignores it, so the string quietly reverts to English with nothing failing. Test: an unknown key in an overlay leaves the English value intact and does not throw.
- **An overlay key missing its `de/` merge file.** `src/de/_data/about.js` exists but `contact.js` does not, so `/de/` mixes locales invisibly. Test: every overlay file has a matching merge file, enforced by reading `docs/de/index.html` and asserting a known German string from *each* expected section.
- **`localePath()` handed something it must not rewrite** — an external `https://` URL, a `mailto:`, or a bare `#anchor`. It must pass those through untouched rather than producing `/dehttps://…`.
- **Doubled locale prefix.** Clicking DE on `/de/` must not produce `/de/de/`. Test: every `href` on `/de/` and `/de/projects/` starts with exactly one `/de`.
- **Switcher colliding with existing chrome.** The coffee FAB is bottom-right and the projects navbar is top-left, so top-right is free — but the pill must not cover the navbar's brand at narrow widths. Test: at 360px wide the pill's left edge is clear of the navbar.
- **The copy button labels are set in JavaScript, not the template.** `coffeeWidget`'s `flash()` assigns `textContent` `"Copy"` / `"Copied"` / `"Failed"` directly, so translating the template's label alone leaves English text on a German page. Task 1 makes these data-driven.
- **`&` in `about.paragraph2`** contains `\n\n` and must keep rendering as two paragraphs; German will contain `ä ö ü ß` and must stay UTF-8.

- [ ] **Step 3: Implement it**

In `.eleventy.js`, above `return {`, add:

```js
    const isGermanUrl = (url) => typeof url === 'string' && /^\/de(\/|$)/.test(url);

    // Internal links must stay inside the current locale. currentUrl is passed in
    // rather than read from `this`, because a Nunjucks global has no reliable `this`.
    // The two locales are not mirror images - the projects page builds as
    // <locale>/projects/index.html - so rewrite only the leading /de segment in
    // either direction instead of prefixing blindly, which would yield /de/de/ from
    // an already-German page.
    // Bind through the `config` parameter, not `this`: the file exports
    // `module.exports = config => {...}` and Eleventy invokes it as a plain
    // function, so `this` is not the config object.
    config.addGlobal('localePath', (currentUrl, path) => {
        if (typeof path !== 'string' || path.charAt(0) !== '/') { return path; }
        if (!isGermanUrl(currentUrl)) { return '/de' + path; }
        return path.replace(/^\/de(?=\/|$)/, '') || '/';
    });
```

And the unit test must therefore pass a stub with `addGlobal`:

```js
register({ addGlobal: (k, v) => (g[k] = v) });
```

which is exactly what Step 1 already does. Do **not** register an `isGerman` global;
templates can test `page.url` directly and an unused global is noise.

- [ ] **Step 3: Implement it**

```js
// Per-key fallback for translations. base is the complete English data file and
// overlay is a sparse German file that only carries translated strings, so any
// key the overlay omits is served from base. Arrays and primitives replace
// wholesale rather than merging element-wise - a translated list is a different
// list, not a patch.
var isPlainObject = function(value) {
    return value !== null && typeof value === 'object' && !Array.isArray(value);
};

var deepMerge = function(base, overlay) {
    if(!isPlainObject(base)) { return overlay; }
    if(!isPlainObject(overlay)) { return overlay; }

    var out = Object.assign({}, base);
    Object.keys(overlay).forEach(function(key) {
        var value = overlay[key];
        // An explicitly undefined value is a stale overlay key, not a deletion.
        if(typeof value === 'undefined') { return; }
        out[key] = isPlainObject(value) ? deepMerge(out[key], value) : value;
    });
    return out;
};

module.exports = { deepMerge: deepMerge };
```
